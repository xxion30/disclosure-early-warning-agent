# Harness 계약 — R2 평가 반영 구현안

최종 PM ZIP과 오후 회의를 따른다. 설명과 안내문 검사를 함께 유지하고 PB 승인도 유지한다.
R3/R4와 합의할 연결안이며 실제 외부 서비스 검증 완료를 뜻하지 않는다.

| 요소 | 구현과 경계 |
| --- | --- |
| Instructions | 버전 있는 프롬프트·Pydantic 출력. 검색 문서는 지시가 아닌 데이터다. |
| Tools | 모델 선택은 읽기 전용 검색 2종. 계산·저장·업무 생성은 코드만 호출. |
| Context | 모델 입력만 마스킹·축약. 인용 식별자·quote 보존. 줄일 수 없으면 수동 확인. |
| State | 내부 점수는 보존하고 공개 투영은 점수 없는 허용 목록. |
| Loop | 실행 구간 120초·AI 생성 8회·도구명+동일 인자 3회. 사람 대기 제외. Graph 한도는 별도 256. |
| Guardrails | 설명·초안·PB 수정·업무 생성 직전 검사. 투자 권유·과장·내부 점수 노출 차단. |
| Recovery | LLM 429/503만 1초·3초 재시도 후 fallback. 도구 TIMEOUT 1회는 R4. DART 원천 복구는 R3/R4. |
| Observability | 노드·모델·프롬프트 버전 기록. 실제 LangSmith 전송·보존 정책은 R4. |

## 출력

설명문은 빈 값·권유·내부 점수 노출·항목 누락/중복·인용을 검사한다.
안내문에는 {고객명}도 요구한다. 실제 이름은 모델에 전달하지 않는다.
설명 재작성 최대 2회 뒤 MANUAL_CHECK. 안내문은 최대 2회 재작성 뒤 해당 고객을 직접 작성 필요로 남긴다.
안전하지 않은 초안은 PB용 get_review에서 가린다. PB 수정도 승인 전에 검사하며 잘못된 요청은 interrupt를 소진하지 않는다.
내부 note를 설명에 붙이지 않는다. 기존 누락 항목 보완 문구도 점수 없는 중립 문장만 사용한다.
금액·날짜·재무 비율은 유지한다. 점수 표현 검사는 정규식 기반으로 모든 우회를 탐지한다고 주장하지 않는다.

## 입력 예산

prepare_input은 복사본을 사용한다. source/rcept_no/location/quote를 임의로 자르거나 마스킹하지 않는다.
개인정보 마스킹 담당은 R4이며, 식별자 보존 검사를 통과하지 못하면 호출 전에 중단한다.
StructuredLLM은 시스템·작업 지침과 직렬화 입력을 합친 추정 토큰도 마지막으로 검사한다.
이는 provider의 실제 토큰 수와 동일한 하드 한도가 아니다. 출력 토큰·요금 한도는 별도다.
줄일 수 없는 예산 초과는 모델 호출 전에 실패하며 허위 인용으로 우회하지 않는다.

get_state와 원시 Graph interrupt는 내부용이다. HTTP/SSE의 tenant/PB 필터와 trace 접근 제어는 R4 담당이다.
승인/업무 DB의 유일 제약과 분산 실행 잠금도 별도 통합 검증 대상이다.
