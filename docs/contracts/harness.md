# Harness 계약 — R2 구현·통합 기준

작성일: 2026-10-23 · 담당: R2 윤찬웅 · 저장·마스킹·trace·도구 복구 협업: R4

> R2 채택 기준이며 문서 변경만으로 구현 완료가 되지 않는다. 관련 담당 검토·코드 반영·통합 검증을 구분한다. [Agent 계약](agent.md)을 함께 따른다.

## 1. 책임과 보호 대상

| 영역 | 주 담당 | 기준 |
| --- | --- | --- |
| 프롬프트·출력 스키마·조건 검증 | R2 | 버전 관리, 허용 항목만 추출, 검색 문서는 데이터로 취급 |
| 검색·일시 색인 | R3 | 원문·키 영속 저장 금지, 출처·정규화 해시 제공 |
| 인용·문맥·출력 검사 | R2 | 문서/API 근거 구분, 점수·권유·과장 검사 |
| 실행 선점·저장·멱등성 | R4 | 중복 작업·오래된 결과·중복 연락 업무 차단 |
| LLM 복구 | R2 | 한정 재시도·대체 모델, 전체 예산 준수 |
| 도구 복구·개인정보·trace | R4 | R3 원천 호출 재시도와 중첩되지 않게 연결 |

## 2. 실행·재시도 예산

| 항목 | 적용 기준 |
| --- | --- |
| 작업 전체 시도 | 최초 포함 최대 3회. API 분석 작업 정책이며 DART 수집기 재시도와 구분 |
| 작업 재시도 대기 | 첫 실패 후 30초, 다음 실패 후 120초. Retry-After나 원천 차단 시간이 더 길면 그것을 우선 |
| 활성 실행 시간 | 판정 실행은 120초 기본 예산. 재시도로 초기화하지 않는다. 사람 승인 대기·예약 대기 시간 제외 |
| AI 요청 | 작업 전체 최초·재작성·통신 재시도·대체 모델을 합쳐 최대 8회 실제 요청 시작 |
| 동일 도구·동일 인자 | 활성 실행 구간에서 최대 3회. 임의 nonce로 동일 입력 제한을 우회하지 않음 |
| 설명·안내문 재작성 | 각각 최대 2회. 전체 AI 예산이 먼저 소진되면 더 일찍 중단 |
| Graph recursion_limit | 기존 256 유지. 시간·호출 제한을 대체하지 않음 |

위 수치는 R2가 채택한 구현 기본값이며 실제 설정의 정본은 담당 설정 모듈 한 곳이다. 위험 점수·임계값은 여전히 rules.yaml 한 곳이며 이 예산과 다르다.

R4 실행 관리가 시도 횟수·다음 실행 시각·사용 예산을 보존해 R2에 전달한다. 프로세스 재시작이나 전체 재시도에서 예산을 리셋하지 않는다. 예산 소진은 무조건 재시도하지 않고 명시적 실패·수동 확인 사유를 기록한다.

승인 후 별도의 초안 재작성은 검토 작업 예산을 사용한다. 사람 대기가 끝났다는 이유로 공개 분석을 다시 실행하지 않는다. PB가 같은 요청을 재전송해 예산을 무한히 새로 만들지 않도록 요청 ID를 멱등 처리한다.

### 오류 분류

- LLM 429/503 등 허용한 일시 오류: 남은 예산 안에서 1초·3초 대기 후 재시도하고 설정된 대체 모델 사용. Retry-After와 120초 활성 예산이 우선한다.
- 도구 TIMEOUT: R4가 최대 1회 재시도. 내부 수집기·HTTP client가 이미 재시도한 경우 전체 예산과 중복 정책을 확인한다.
- DART 013: 정상 빈 결과. 재시도하지 않는다.
- DART 020: 즉시 반복하지 않는다. 수집기 계약에 따라 제한 재시도 후 작업을 보류·종료한다. 일일 한도 소진이 의심되면 재호출을 중단한다.
- 입력 오류·권한 오류·원문 불일치·판정 충돌·근거 부족: 통신 재시도하지 않는다. 유형에 따라 요청 거절 또는 MANUAL_CHECK.
- PB 승인 interrupt: 실패가 아니며 자동 재시도하지 않는다.

## 3. 모델 입력과 검색

시스템·작업 프롬프트와 직렬화 데이터를 모두 포함해 토큰 예산을 검사한다. 기존 입력 6,000토큰 추정 예산을 유지하되 추정치가 공급자의 실제 집계와 같다고 보장하지 않는다. 출력 상한·사용량도 기록한다.

공시 검색은 여러 호출을 합쳐 모델 입력 한 번당 최대 5개를 사용한다. 검색 후보는 더 많이 확보할 수 있다. 중복·무관 조각부터 제외하며 인용문·출처 식별자를 임의 절단해 예산을 맞추지 않는다. 예산을 만족할 수 없으면 호출 전에 수동 확인으로 전환한다.

원문 도구 응답을 Graph State에 그대로 반환하지 않는다. 일시 검증 후 필요한 인용·출처·해시만 영속 State로 보낸다. 모델 입력을 구성하는 복사본과 저장 데이터를 구분한다.

## 4. 출력·PB 수정문 검사

- 설명·안내문·PB 수정문·업무 생성 직전 문안에 동일한 금지 표현 검사를 적용한다.
- 점수·배점·가중치·반영률·원시 계산 메모, 매수·매도 권유, 과장·수익 보장 표현을 차단한다.
- 실제 공시 금액·날짜·재무 비율은 유지한다. 숫자 전체를 삭제하지 않는다.
- 설명의 빈 값·근거 누락·항목 중복·인용 불일치도 검사한다.
- 고객 실명을 모델에 보내지 않고 안내문에는 {고객명}을 사용한다. 실제 치환·연락처 처리는 권한이 확인된 R4 경계에서 수행한다.
- 설명 재작성 한도 초과는 MANUAL_CHECK. 안내문 한도 초과는 해당 고객을 직접 작성 필요로 남긴다.
- 검사 실패 초안은 승인 가능 데이터로 노출하지 않는다. 잘못된 PB 수정은 요청을 거절하고 기존 승인 대기를 소진하지 않는다.
- 정규식 검사는 모든 우회 표현을 보장하지 않는다. 동일 평가셋으로 누락·오탐을 측정한다.

## 5. 원문·색인·체크포인트

1. R3가 document.xml을 메모리에서 정규화·색인한다.
2. R2와 필요한 R4 검증 경로가 조회하고 최소 근거를 보존한다.
3. 판정·설명·분석 입력 버전 저장 완료 후 색인을 해제한다.
4. 초안·승인 재개는 보존 근거와 참고 문서 가이드를 사용한다. 추가 사실이 필요하면 새 분석을 요청한다.

검색 text·전체 body·원시 ToolMessage가 State·checkpoint·callback으로 저장되지 않게 처음부터 경계를 둔다. 종료 시 State를 비우는 것만으로 이전 checkpoint가 삭제됐다고 보지 않는다.

실패·취소 시 finally 정리와 R3 TTL/LRU를 함께 사용한다. TTL/LRU도 사용 중인 색인을 제거하지 않도록 한다. 접수번호 공유 색인은 사용권·참조 카운트 또는 동등한 보호를 적용한다. 해제 요청은 멱등 처리하고 다른 실행이 사용 중이면 실제 제거를 늦춘다. 기존 release 도구 응답 필드는 유지하며 실제 해제가 지연되는 경우 released_chunks를 실제 제거 수로 반환한다.

MANUAL_CHECK에도 색인은 무기한 보존하지 않는다. 재분석 때 재생성하고 해시를 비교한다. 원문 변경·근거 부족이면 기존 승인 재개에 새 사실을 몰래 섞지 않는다.

## 6. 정보 허용 범위

| 경계 | 허용 | 제외 |
| --- | --- | --- |
| 내부 판정 저장 | 계산 결과, 구조화 입력, 출처·인용, 규칙·자료 버전, 기준 시점 | 원문 전체·불필요한 검색 조각·비밀 키 |
| 설명·안내문 모델 | 단계·필요 사실·최소 근거·실제 공시 수치 | 내부 점수·배점·원시 메모·고객 실명 |
| PB API·SSE | 권한 있는 결과·출처·진행·검토 상태 | 점수·내부 정렬값·전체 State·다른 조직 고객 |
| 감사 로그 | tenant·행위자·판정/작업 ID·행위·시각·결과·입력 참조 | 키·원문·검색 전문·불필요한 개인정보 |
| trace | 노드·도구명·지연·상태·토큰·비용·모델/프롬프트 버전·오류 코드 | 원문·검색 전문·고객 식별정보·비밀 키 |

재현용 상세 입력은 접근이 통제된 판정 저장소에 보존하고 일반 trace에 복제하지 않는다. tracing이 모델·도구 입력을 자동 수집하면 해당 경로의 캡처를 끄거나 저장 전에 허용 목록으로 정제한다. 정제가 확인되기 전에는 민감한 입력의 외부 trace 전송을 비활성화한다.

## 7. 중복 구현 전환

- R4 Phase1Model의 출력 보정·분류기와 R2 추출·검증은 R2 경로로 통합한다. 불일치를 자동 수정해 검증을 우회하지 않는다.
- R4 EvidenceTools가 하던 과거 인용 검증은 검증 기능을 보존한 채 단일 경로로 연결한다.
- 체크포인터 생성은 R4, Graph 실행은 R2. 이중 생성·이중 종료를 금지한다.
- release_disclosure_index와 purge_disclosure_text는 호출자를 전환한 뒤 정리한다. 본문 삭제 도구를 해시·성공 시각 기록 도구로 계속 사용하지 않는다.

## 8. 검증 기준

- [ ] 최대 5개 조각과 입력 예산이 여러 검색·재작성에서도 유지된다.
- [ ] 재시도·대체 모델·재시작을 합쳐 실제 요청 8회 한도를 넘지 않는다.
- [ ] 실패·취소·동시 실행에서 색인 누수나 다른 작업의 색인 삭제가 없다.
- [ ] checkpoint와 trace 저장 결과에서 원문 전문·불필요한 조각·PII를 직접 확인한다.
- [ ] 안전하지 않은 PB 수정이 승인 대기를 소진하거나 업무를 만들지 않는다.
- [ ] 저장 직후 장애·재개에서도 동일 승인·연락 업무가 중복되지 않는다.
- [ ] 실제 호출 검증과 가짜 도구 테스트 결과를 별도로 기록한다.
