## 평가 결과 — R5 사례 · 규칙 엔진만 (2026-10-23)

### 무엇을 채점했나
- **사례**: R3의 공시 한 건 사례(`eval/cases/r3_cases.json`)와 R5 사례(`eval/cases/r5_cases.json`).
  R5는 R3와 겹치지 않게 **기간 사례**를 맡는다 — 회귀 타임라인 3건(금양·CJ CGV·SK, 각 12개월)과 정상 회사 3건(현대차·NAVER·LG전자, 2024 사업보고서까지 12개월).
- **만드는 법**: `uv run python scripts/demo/build_r5_cases.py` — DART 공시 목록(list.json)의 실제 접수번호·제목·날짜, 재무 지표는 R3 수집기(`collector.indicators`)를 DART 재무제표·감사의견 API에 돌린 값, 사건 공시 값은 항목 API 원본. 지어낸 값은 없다. (DART_API_KEY 필요)
- **채점하는 법**: `uv run python scripts/demo/eval_cases.py --write` — 공시 종류는 `rules.yaml`의 제목 분류, 단계는 `risk_engine`이 계산한다. AI·모델 비용·DART 호출 없음.

### 한계 (규칙만으로 정할 수 없는 것)
- **AI 판단 필요**: 거래정지 해제·기간 변경·불성실공시 당일 정지·풍문, 횡령 진행사항, 결과보고서처럼 R1 결정(PR #31)상 경보에서 빠지는 후속 공시는 AI가 원문에서 뽑는 값(`lifted`·`resolved`)으로 구분한다. 채점에서 빼고 따로 센다. 정정 공시는 같은 사건이라 새 신호로 넣지 않는다.
- **빠진 값**: 판정에 필요한 값(유상증자 비율·제3자배정 외에는 항목 API에서 바로 읽지 않음)은 비워 두고 기본 점수만 센다. 실제 흐름에서는 AI가 원문에서 채운다.
- **정정본 값**: DART 항목 API는 최신 정정본만 돌려줘서, CJ CGV 2023-06-20 유상증자처럼 공시 당일 값이 없는 경우가 있다. 나중 정정본 값은 미래 정보라 쓰지 않았다.
- **금양 원본 재무 값 검증 대기**: 2024-03-27 원본과 2024-04-17 정정본에 같은 재무 API 결과가 연결되어 있다. R3가 각 문서를 직접 비교하기 전에는 359일을 확정 성과로 쓰지 않는다. 재무 값·공시 시점·감사의견을 확인한 뒤, 값이 맞으면 보류를 해제하고 다르면 원본 값으로 재생성·재평가해 R1에게 알린다.
- **재생성 검사 범위**: 테스트는 저장된 공시·facts·공시 건수로 실제 생성기와 같은 조립 함수를 실행해 저장본과 비교한다. DART 재수집이나 당시 원본 검증을 대신하지 않는다. R3 검증 전에는 최신 API 재수집으로 저장된 재무 값을 덮어쓰지 않는다.
- **R3 타임라인 기준일**: 오스템임플란트·위니아의 `as_of`는 타임라인 끝 날짜다. 사건일과의 선행 기간으로 해석하지 않도록 날짜·종류만 표시한다. 사건 기준일 확정은 R1·R3 후속 확인 사항이다.

### 기준값 변경 전후 비교 (규칙 엔진만)
- **방법**: `uv run python scripts/demo/compare_thresholds.py --write` — 같은 사례 50건을 규칙 설정만 바꿔 다시 채점한다. `risk_engine/rules.yaml`(R4)은 고치지 않고, 설정마다 임시 사본을 `RULES_PATH`로 읽는다. 설계서 STEP 06 예시(기준값 변경, 복합 규칙 켬/끔, 관찰 표시 켬/끔)를 따랐다.
- **읽는 법**: 아래 설정에서는 금양의 최초 **사건 경보**가 141일 전으로 유지된다. 최초 **전체 경보**는 지금 기준에서 🟡 359일 전(저장 데이터 재생·R3 검증 대기)이며, 🟡 기준을 6으로 올리면 🟠 141일 전으로 바뀐다. 두 지표를 구분한다. 현대차 오탐은 🟠 기준 5, 🟡 기준 6, 복합 2.0, 복합 규칙 끔에서 사라지지만, 🟡 기준 4에서는 SK 오탐이 추가되어 2/6이 된다. 적중은 아래 설정에서 3/3이다.
- **R1 결정**: 기준값은 설계서 초안(🟠 4 · 🟡 5 · 복합 1.5 · 관찰 75%)을 유지한다([위험 정책 2장](risk_policy.md)). 미탐이 오탐보다 심각하므로(원칙 1) 현대차 오탐을 없애려고 기준을 올리지 않고, PB 판단 영역으로 둔다(원칙 2·3).
- **한계**: 경보가 있어야 하는 기간 사례가 3건, 정상 회사가 6건뿐이라 기준값을 정할 근거로는 부족하다. 기간 계산 정답은 기준일 단계뿐 아니라 지정된 최초 경보 종류·날짜·선행 기간도 검사하므로 설정을 바꾸면 일치율이 낮아질 수 있다. 사례를 늘린 뒤 다시 돌려야 하며, 기준값은 R1이 정한다(`docs/risk_policy.md`).
