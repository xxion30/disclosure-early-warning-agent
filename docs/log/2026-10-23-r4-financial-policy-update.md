# R4 재무 정책 변경 및 원리금 미지급 비용 회신

## 기준과 범위

- 기준: 통합 브랜치 `e5c6526` (#61 반영).
- 작업 브랜치: `codex/r4-financial-policy-update`.
- 근거: 사용자 요청과 `docs/risk_policy.md` 2·3-1·3-2, `docs/tasks/r1-decisions-requests.md` R4 요청 1~3.
- 범위: R4 규칙·재무 선택·API 근거·테스트·계약. R2 그래프, R3 지표 계산·수집기, R5 평가 정답·화면은 수정하지 않는다.

## 1. 자본잠식 OFS·CFS

- R3는 이미 두 기준의 자본잠식률을 계산해 FinancialSnapshot에 저장한다. R4는 저장된 최신 보고 기간의 OFS(SEPARATE)·CFS(CONSOLIDATED)를 각각 읽는다. 계산식은 R3 책임이며 중복 구현하지 않았다.
- 같은 기간·기준별 최신 revision을 먼저 고른다. 정정 전 높은 값을 남겨 두지 않는다.
- 두 잠식률 중 높은 값으로 YAML의 가장 높은 구간 하나를 적용한다. 두 기준을 합산하지 않는다. 현행 50 이상 +3, 100 이상 +4는 유지한다.
- 자료가 없는 기준은 과거 보고서나 0으로 대체하지 않고 MISSING/null로 표시한다. 유효한 한쪽은 활용하고 양쪽 모두 산정 불가일 때 수동 확인한다.
- 선택한 fs_div와 양쪽 basis_checks(fs_div/period/rcept_no/revision/status/impairment_pct)를 breakdown에 보존한다. `/states/{stock_code}`의 항목에서도 이 필드를 제공한다. 점수·가중치·정렬값은 공개하지 않는다.
- 다른 지표의 같은 기간 CFS 우선, 연간 영업현금흐름 선택, 전체 경보 임계값은 유지한다. 자본잠식 항목 활성화가 단독으로 YELLOW 전체 경보를 강제한다는 뜻은 아니다.

## 2. 금융비용 기준 보상배율

- INTEREST_BURDEN의 enabled를 true로 변경했다.
- 영업이익÷금융비용(금융원가)이 **1 미만일 때 +2**, 정확히 1 이상이면 가점하지 않는다. 수치는 rules.yaml 한 곳에 유지한다.
- 영업이익이 0·음수이고 분모가 양수인 유효 비율도 1 미만 규칙을 적용한다.
- 계정 누락·금융비용<=0은 기존 R3의 MISSING을 유지한다. 모델이 넘긴 임의 비율 대신 DB 스냅샷을 사용하며, 결측이면 산정 불가/수동 확인으로 남긴다.

## 3. 원리금 미지급 RED 편입과 비용

### 확인·반영

- PAYMENT_DEFAULT는 이미 red 목록, Phase 1 제목 분류, 허용 신호 카탈로그에 등록돼 있다. 별도 점수 임계값 없이 RED로 판정하는 경로가 있다.
- 기존 제목 키워드 원리금미지급에 **대출원리금연체사실발생**을 추가했다. 저장소 실제 위니아 목록의 `20231018900507`(대출원리금연체사실발생), `20231023900517`(사채원리금미지급발생)을 읽어 제목 분류와 RED 계산을 검증한다. 원문·금액·접수번호를 만들지 않았다.
- 단순 미상환 잔액·만기 도래를 원리금 미지급으로 분류하지 않는 시험과, 근거 없는 해소가 RED를 끄지 못하는 시험을 추가했다.

### R1에게 전달할 비용 회신

> R4의 원리금 미지급 RED 규칙은 이미 등록되어 있어 새 엔진·DB·외부 API를 만들 비용은 없습니다. 실제 제목 변형 보완과 규칙·분류·해소 회귀 검증 및 문서 정리까지는 **약 2~4인시의 소규모 작업**으로 추정하며, 이 브랜치에서 해당 범위를 반영했습니다. 이는 코드 확인에 근거한 개발 규모 추정이지 측정한 실작업 시간이나 운영 연결 완료 보장이 아닙니다.
>
> 수집부터 실제 원문 분석·근거 저장·알림까지의 종단 연결은 별도입니다. 현재 R3 구조화 사실 목록에는 PAYMENT_DEFAULT 전용 항목 API가 없고, R2 receive는 structured_facts가 UNAVAILABLE이면 수동 확인으로 중단합니다. 따라서 이 종류의 실제 공시를 새 분석 경로로 끝까지 처리하려면 R2·R3와 원문 분석 분기를 연결·검증해야 합니다. 이 범위의 일정은 원문 사례와 실행 경로를 확인한 뒤 공동 산정해야 하며, 이번 규칙 시험을 운영 알림 완료로 보고하지 않습니다.
