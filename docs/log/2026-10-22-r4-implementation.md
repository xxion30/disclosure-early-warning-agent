## 최근 대화의 적용·보류·제외

| 사항 | 처리 |
| --- | --- |
| 원공시·정정·후속 공시 연결 | 사건 식별자로 중복 방지. 원공시 관계는 R3가 확인한 DB 정보만 신뢰한다. 모델이 전달한 사건 관계로 임의 병합하지 않는다. |
| 여러 위험 항목 간 중복 합산 | **정책 보류**. 통합 규칙·자동 중복 제외를 임의로 만들지 않았다. 현재는 항목별 규칙을 독립 합산하므로 같은 거래가 여러 항목에 걸릴 때 과대 합산 가능성이 있다. 실제 데이터 확보 후 사례·계산 결과를 점검한다. |
| 재무 기간·계산 예외 | 같은 기간·누적 기준 비교, 연속 연도는 연간 자료, 판단 불가는 수동 확인 원칙을 적용한다. |
| 승인 중 보유·담당 PB 변경 | **범위 제외**. 동적 초안 무효화·신규 보유 고객 자동 추가를 구현하지 않았다. 기존 PB 소유권 검사는 유지한다. |
| 해소 후 재발 전용 처리 | **범위 제외**. 재발 이력을 따로 감지하는 기능을 추가하지 않았다. 기존 기본 새 경보 조건은 유지한다. |

## 호환과 연동 대기 사항

### R2와 연결할 부분

- 구형 R2 그래프를 유지하기 위해 내부 `level`, `total_score`, `combo_upgraded` 호환 필드는 남겼다. 새 판정의 정본은 `stage`다. 감사의견 거절은 YELLOW이며 내부 호환 level은 High다.
- 이전 순수 규칙 함수와 YAML의 구형 구역은 기존 평가·연결 호환용으로 남아 있다. production business 계산 도구는 새 `stages.calculate`를 사용한다. 구형 규칙 테스트 통과는 새 경보 정책 검증과 구분한다.
- 새 위험 항목 전체에 대한 분류·플래그 추출·stage 분기·프롬프트, 알림 버전별 초안 갱신과 승인 상태 전이는 R2 그래프와 연결해야 한다.
- 공개 분석과 회사별 고객 실행을 나눌 DB 구조는 준비했다. `tenant_runs`는 아직 회사별 그래프 실행을 자동 구동하지 않는다.
- 구형 runtime은 공시번호만으로 스레드를 식별한다. 회사별 실행 연결 전까지 **default 외 회사의 구형 실행·승인·SSE는 503으로 차단**한다. 여러 회사의 승인 흐름이 완성됐다는 의미가 아니다.
- 승인 대기 전 원문 조각의 State·체크포인트 제거, 재작성 시 원문 재조회는 R2·R3와 연결해야 한다. 이번 작업이 전체 원문 수명 정책을 완성한 것은 아니다.

### R3와 연결할 부분

- 실제 OpenDART 수집·증분·백필·09:05 스케줄러와 메모리 RAG는 R3 영역이다. 이번 작업에서는 수정하지 않았다.
- `POST /collect/run`의 dispatcher가 없으면 503이다. 실제 수집 성공처럼 표시하지 않는다. dispatcher는 `(run_id, stock_codes)`를 받아 실행을 인계하고, 이력과 종목별 성공 커서를 기록해야 한다.
- 수집 완료 후 일일 `refresh_states` 호출이 필요하다. 함수만 추가했으며 자동 스케줄 등록은 하지 않았다.
- 실제 API의 정정 관계와 재무 기간·단위·필드·출처를 확인해 새 저장 계약에 연결해야 한다. 재무 스냅샷 입력 형식은 `docs/contracts/db.md`에 기록했다.
- `shared/models/collect.py`는 수정하지 않았다. 재무·수집 저장 계약 모델은 R4의 `shared/models/operations.py`에 두었다. R3 확인 뒤 모델 위치를 정리한다.
- integration Compose 프로필의 collector 진입점과 RAG 외부 바인딩은 R3 구현이 필요하다. 현재 전체 통합 배포용으로 사용할 수 없다.

### 기타

- R5는 새 상태 API 응답과 알림 버전을 화면에 연결해야 한다. 화면 코드는 수정하지 않았다.
- `GRAPH_ADAPTER=fake`는 기존 시연 경로다. 새 위험 규칙 전체를 검증하는 데 사용하지 않는다.
- CODEOWNERS의 collect.py 담당 덮어쓰기 문제는 R1 소유 파일이므로 수정하지 않았다.
- 운영 PostgreSQL에 기존 SQLite 데이터를 자동 이관하지 않는다. 실제 데이터 이전은 백업 후 별도 수행해야 한다.
- 기본 테넌트와 테스트·개발 설정을 제공한다. 회사 관리자 지정은 DB의 PB.role로 관리하며 사용자·보유 종목 관리 기능을 추가하지 않았다.
