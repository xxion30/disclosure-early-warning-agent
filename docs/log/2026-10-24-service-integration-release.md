# 서비스 전체 통합·배포 작업 기록

## 범위와 기준

- 사용자 승인: 기존 역할별 소유권과 별도 협의 절차를 넘어 전체 서비스를 통합하고, 요구사항 충족과 실제 실행을 확인할 때까지 보완한다. 판단 근거와 검증 결과를 기록하고 구현과 다른 문서를 정리한다.
- 시작: main의 통합 완료 커밋 b78adcc, 작업 브랜치 `codex/service-integration-release`.
- 외부 배포 서버·도메인은 사용자 확인 중이다. 답변 전에도 로컬 실행·배포 구성·통합 시험은 진행한다. 비용이 발생하는 외부 서버를 임의로 만들지 않는다.
- 비밀 값은 출력·커밋하지 않는다. 실제 데이터 DB를 초기화하지 않고 검증 DB를 분리한다.

## 진행 단계

1. 전체 요구사항·실행 경로와 기존 테스트 기준을 확인한다.
2. 사실 미수집 원문 경로, 수치 추출·재무/과거 근거 검증, 공개 분석·조직별 검토의 누락 연결을 보완한다.
3. 화면의 분석 실행·진행 표시·검토·승인·연락 업무를 실제 API로 연결한다.
4. Docker 시작 순서·마이그레이션·프런트 빌드·운영 계정 준비·상태 확인을 정리한다.
5. 격리 DB와 실제 HTTP/MCP 경계를 사용해 통합 시험·화면 확인을 반복한다. 가능하면 실제 공급자 호출도 최소 범위로 확인한다.
6. 구현과 문서를 동기화하고 재현 가능한 실행·배포 절차와 남은 제약을 남긴다.

## 초기 확인과 판단

- `docker-compose.yml`은 API가 hosted runtime에서 MCP를 필요로 하지만 business가 API health를 기다려 시작 순환이 생긴다. 마이그레이션 완료 → MCP 준비 → API/worker → 화면 순서로 분리한다. 단순 재시도로 순환을 숨기지 않는다.
- run_stack.py의 Chroma 사전 적재와 fake 기본 안내는 현재 메모리 임시 색인·hosted 경로와 맞지 않는다. 실제 서비스의 기본 실행과 별도 데모 모드를 구분한다.
- 구조화 사실이 없는 것은 위험 없음이 아니다. 원문 검증으로 진행할 수 있게 하되 근거가 부족하면 수동 확인을 유지한다.
- 현재 설정에 OpenAI 키만 확인됐고 DART 키는 사용자 설정 예정이다. 키 값을 요청하거나 기록하지 않는다.
- 로컬 Docker CLI는 있으나 엔진이 정지 상태다. 설치된 Docker 앱의 시작과 사용 가능 여부를 확인한다.

## 연결 보완과 판단

- 수집 사실이 NULL인 공시는 UNAVAILABLE 상태를 유지하며 원문 분석으로 전달한다. 실행 시 고정된 사실 버전도 NULL이어야 한다. 사실 없음과 위험 없음은 구분한다.
- 원문에 직접 기재된 백분율은 숫자·%·인용문을 함께 검증해 API 결측의 보완으로 사용한다. 모델이 금액을 나눠 비율을 계산하거나 결측을 0으로 대체하지 않는다. API와 원문 값이 충돌하면 수동 확인한다.
- 재무 지표는 수집 스냅샷의 기간·연결/별도·정정 버전·실제 값·해시를 갖는 financial 근거로 전달하고 별도 MCP 검증 도구로 원본 스냅샷과 대조한다. 재무 계정 행을 공시 인용문으로 가장하지 않는다. 과거 API 근거도 해당 접수번호의 사실과 대조한다.
- 같은 기업의 백필 작업을 한 번에 모두 생성하면 뒤 작업의 입력 스냅샷에 앞 작업의 사건 이력이 빠진다. 기업별 하나씩 생성하고 실행도 기업별 직렬화한다. 과거 공시는 당시 기준일로, 마지막 공시는 현재 기준일로 평가한다. 다른 기업의 작업은 계속 선점할 수 있다.
- 공개 판정이 있는 경보 상세는 조직별 검토 DB를 조회한다. 화면의 직접 분석은 기존 /runs 대신 /analysis/jobs로 요청·상태 조회하며 조직별 검토 링크로 연결한다. 운영 빌드에서 화면 mock 모드는 비활성화한다.
- run_stack은 실제 hosted Graph·임시 색인·DB 실행기를 기본으로 연결하고 기존 DB를 reset하거나 Chroma ingest하지 않는다. fake는 명시적 옵션으로만 남긴다. 새 관리자 생성은 별도 명령으로 제공하며 기존 계정을 덮어쓰지 않는다.
- 컨테이너는 migrate → business/rag MCP 준비 → API/worker → web 순서로 시작한다. /health와 별도로 /ready에서 DB 및 실행기 중단을 감지한다. 운영 비밀값은 커밋하지 않는 data/release.env에 최초 한 번 생성한다.
- 신규 배포의 보유 종목은 아직 companies에 없을 수 있다. 수동 수집 API의 Company 내부 조인으로 첫 수집 자체가 차단되던 문제를 제거했다. 보유 종목 전체를 R3에 넘겨 corpCode.xml로 확인·제외하게 한다.
- 공시가 없는 날에도 시간 감쇠와 규칙 버전을 반영하도록 새 기준일의 불변 분석 작업을 생성한다. 임의 refresh로 현재 상태만 바꿔 승인 식별자를 어긋나게 하지 않는다. 동일한 의미의 판정(state_version 동일)은 기존 조직 검토·결정을 재사용하고, 근거·단계·값·결측·규칙이 바뀌어 state_version이 달라질 때만 기존 검토를 종료한다. 단순 재평가로 매일 중복 연락 업무를 만들지 않기 위함이다.
- 정정 본문의 최초제출일과 같은 회사의 정규화 제목·접수일이 유일하게 일치하면 공유 사건 연결 함수를 호출한다. 원문 중 해당 짧은 구간과 위치만 event_link_evidence에 보존하며, 불명확한 원본을 임의로 고르지 않는다. 마이그레이션 20261024_07을 추가했다.
- 고객·보유 내역 입력 명령은 기본 검증 후 rollback한다. --apply로 명시한 경우만 저장하며 기존 계정·다른 조직 데이터·입력에 빠진 보유 내역을 덮어쓰거나 지우지 않는다.
- 기존 최신 상태가 있는 DB에서 과거 백필을 시작해도 과거 판정이 최신 상태를 덮지 않게 했다. 과거 공개 판정·검증 신호는 저장하되 현재 승인에 쓰지 않는 state_version=0으로 구분한다. 백필 종료 후 현재 입력 해시가 달라지면 같은 날이어도 최신 판정을 다시 요청한다. 데이터를 reset해 문제를 감추지 않고 신규·기존 환경 모두 사건 이력을 쌓기 위한 선택이다.
