# R4 최종 검증 후 수정 기록 — 2026-10-22

## 범위와 결과

사용자의 “지금 여기서 수정할 수 있는 부분은 수정하고 로그를 남겨 달라”는 요청에 따라 `R4_V01` 브랜치에서 수정했다. 기준 커밋은 `4d2eb96`이다. 이번 변경은 아직 커밋·푸시하지 않았다.

기준 명세는 오후 회의 변경 사항, `docs/tasks/r4-design-decisions.md`, 이후 대화에서 채택·보류한 결정이다. 이전 [최종 검증 기록](2026-10-22-r4-final-review.md)의 재현 문제를 R4 소유 코드와 adapter에서 보완했다. 전체 제품 통합 완료를 의미하지 않는다.

## 검증 지적별 조치

| 항목 | 수정 및 확인 결과 |
| --- | --- |
| 1. 과거 근거를 Agent가 거부 | `EvidenceTools`에서 실제 `search_disclosure_text`를 호출해 출처·접수번호·위치·인용문을 재검증한다. 검증한 인용 부분과 원문 조각 해시만 반환하며, 과거 주장을 원문처럼 꾸미지 않는다. 재조회 실패·인용 불일치는 수동 확인으로 남긴다. |
| 2. 승인 재개가 감쇠 결과를 되돌림 | 기준일·규칙 해시·상태 버전과 조건부 저장을 추가했다. 오래된 기준일이나 계산 이후 변경된 상태의 덮어쓰기를 거부한다. 동일 판정의 승인 상태 저장은 공개 위험 상태를 다시 발행하지 않는다. |
| 3. 해소·변경 후 오래된 초안 승인 | 평가가 참조하는 상태 버전과 현재 공개 상태를 비교한다. Graph 초안의 판정 해시도 저장된 평가와 대조한다. 불일치·해소·비경보는 승인·재작성 요청을 409로 차단하고 연락 업무 생성 도구도 최신 버전을 확인한다. 전원 반려만 하는 요청은 오래된 검토를 종료할 수 있다. |
| 4. 설명 문자열의 점수 노출 | R4 모델 adapter의 누락 항목 설명에서 점수를 제거했다. API 설명에도 점수·반영률 표현 검사를 적용해 해당 설명을 수동 확인 문구로 대체한다. 원문 금액·비율과 별도 evidence는 유지한다. |
| 5. 새 위험 항목 실행 연결 | 새 YAML 분류·유형별 허용 목록을 R4 assembly에 연결했다. 부도·회생·영업정지·소송 등을 허용하고, 해외 상장폐지는 국내 상장폐지 RED와 구별한다. AI 입력에 허용 필드를 전달하며 재무 계산 지표는 AI 추출 대상에서 제외한다. 실제 모델·실제 공시 전체 경로의 품질 평가는 남아 있다. |
| 6. 재무 스냅샷 선택 | 지표별 최신 유효 기간을 고르고 동일 기간에는 연결을 별도보다 우선한다. 연간 전용 지표는 최신 분기 보고서 때문에 사라지지 않는다. 연간·분기 기간 정렬과 최신 정정의 결측 처리도 검증했다. |
| 7. 0점 항목의 오경보 | 위험 조건이 없는 0점 관측은 활성 위험에서 제외한다. 정상 감사의견 추가만으로 알림 버전이 증가하지 않는다. |
| 8. 동시 읽음 처리 | SQLite·PostgreSQL의 원자적 upsert로 읽음 버전의 최댓값을 저장한다. 과거 세션에서 낮은 버전을 확인해도 읽음 버전이 감소하지 않는다. |
| 9. 기존 경보 정렬·요약 | `/alerts`도 새 단계 우선순위와 기준 대비 정렬값을 사용한다. 요약은 RED·ORANGE·YELLOW 활성 항목을 반영한다. 구형 평가에 한해 기존 등급을 호환한다. |

상태 버전과 알림 버전은 별도다. 실제 판정 내용이 바뀌면 초안 유효성을 다시 확인하고, 계산일만 바뀐 동일 판정은 기존 초안을 무효화하지 않는다. `/states` 상세의 설명도 현재 상태 버전과 일치하는 평가에서 선택한다.

## 수집 장애 복구와 DB 변경

- `CollectRun`에 임대를 추가했다. 실행자는 `heartbeat_run`으로 갱신하고 종목별 `finish_stock` 이후 `finish_run`으로 종료한다.
- 만료 작업은 다음 수집 요청 또는 `python -m scripts.ops.recover_collections`에서 실패 처리하고 예약을 해제한다. 만료·종료된 이전 실행자는 커서를 갱신할 수 없다. 복구 실행 전에도 만료된 작업의 완료를 거부한다.
- 실행→종목 순서로 잠금을 맞췄다. 실패 종목은 성공 커서를 전진시키지 않으며 커서가 과거로 이동하는 것도 거부한다.
- 추가 마이그레이션 `20261022_02`에 판정 기준일·규칙 해시·상태 버전·평가 참조·수집 임대를 넣었다. 기존 `20261022_01`은 수정하지 않았다. 이력 보존을 위해 자동 downgrade는 지원하지 않는다.
- 배포 전 `uv run alembic upgrade head`가 필요하다. 기존 판정은 새 평가 참조가 없으므로 현재 경보의 초안을 다시 분석해야 승인할 수 있다. 사용자의 기존 DB에는 적용하지 않았다.
- 계약 문서와 `docs/run.md`, `.env.example`을 함께 갱신했다. 기본 임대는 `COLLECTION_LEASE_SECONDS=600`이다.

정상 Graph 초안이 API의 최신 판정 검사를 통과하는 연결 테스트와, 과거 Graph 초안·해소된 위험을 거부하는 회귀 테스트를 포함했다. 과거 근거 테스트는 실제 검색 호출 여부와 원문 불일치 거부도 확인한다. 내부 fixture는 실제 회사에 대한 새 공시 사실을 주장하지 않는다.

PostgreSQL 검증은 임시 서버의 테스트별 독립 스키마에서 수행했고 해당 스키마만 정리했다. 임시 서버는 종료했다. 유료 모델, DART 외부 호출, 외부 메시지, 사용자 데이터 변경은 수행하지 않았다. 이번 검증 결과는 실제 DART 수집·실제 모델 성능 평가를 대체하지 않는다.

## 남은 연동과 담당 간 확인

- **R2:** 회사별 비공개 Graph 실행·승인, 새 위험 항목의 실제 프롬프트 품질 및 여러 공시를 잇는 전체 실행 검증. R4 adapter 연결만으로 이 작업까지 완료됐다고 보지 않는다.
- **R3:** 실제 DART 사건 연결 정보·재무 계산과 출처, 메모리 RAG 재조회·수명 처리, dispatcher·09:05 스케줄러의 heartbeat·완료·복구 함수 연결. 복구 함수는 재수집을 자동 실행하지 않는다.
- **공동 모델:** `financial_snapshots`, `collect_runs`의 현재 정의는 `shared/models/operations.py`다. R3가 `collect.py`에 중복 선언하지 않도록 계약에 명시했다. 상대 담당자의 확인을 받았다는 기록은 아직 없다.
- **R5/통합:** UI와 새 단계 API 연결, 실제 5개 회사의 새 정책 평가가 남아 있다.
- R2·R3·R5 소스는 직접 수정하지 않았다. 기존 `.dockerignore`·`alembic.ini`의 CODEOWNERS 기본 소유와 계약 변경은 통합 시 담당 리뷰가 필요하다. 기존 Agent의 직접 `risk_engine` import 정리는 R2 연동 과제로 남긴다.
- `save_risk_state`는 신뢰된 코드가 계산한 값을 저장하는 경계다. `create_contact_task`의 고객별 PB 승인 증명은 Graph·adapter가 담당한다. 임의 MCP 호출자에 대한 별도 승인 증명 검사를 새로 구현한 것은 아니므로 자유로운 모델 도구 선택에 노출하면 안 된다.

## 사용자 결정으로 보류·제외한 범위

- **항목 간 중복 합산:** 실제 데이터를 보고 정하기로 했으므로 임의의 상호 제외 규칙을 추가하지 않았다. 같은 사건의 정정 중복 방지와는 별개다.
- **승인 중 보유 종목·담당 PB 변경:** 추가 대응을 넣지 않았다. 기존 담당 고객 권한 확인은 유지한다.
- **해소 후 동일 위험 재발 전용 처리:** 추가하지 않았다. 기존의 단계 상승·새 위험 종류·별도 RED 사건 알림 조건은 유지한다.
- **재무 비교·예외:** 채택한 연간끼리·동일 기간끼리 비교와 결측·분모 예외의 수동 확인 원칙을 유지한다. 실제 계산 입력의 품질은 R3 데이터로 확인해야 한다.
