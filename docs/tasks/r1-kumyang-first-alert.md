기준: `Pre-merge-P01-v01`(`fc97061` 이후 `a8411e2`, 관련 내용은 같음). 실패: `tests/demo/test_r5_eval.py::test_r1_gold_answers_for_r5_cases` (118행). R4의 [재무 정책 변경 회신](../log/2026-10-23-r4-financial-policy-update.md)의 "R1·R5 정답 확인 필요"에 대한 R1의 답이다. 정책 문구는 [위험 정책](../risk_policy.md) 2·3-3~3-5절에 반영했다.

## 1. 결론

**권장 방향("당시 재무 데이터 검증 → 최초 전체/사건 경보 구분 → 정책·정답·테스트·보고서 동기화")을 채택한다.** 다만 아래 보정을 붙인다.

| 보정 | 이유 |
| --- | --- |
| **정책 확정과 데이터 검증을 분리한다.** 이자부담 가점 유지(B)는 지금 확정하고, 데이터 검증은 **359일 정답**만 기다리게 한다 | 규칙은 모든 사례에 적용되는 일반 정책이다. 정상 6건의 오탐(1/6)과 적중(3/3)이 가점을 켜고 꺼도 같아서, 규칙을 고칠 근거가 없다. 검증이 필요한 건 한 사례의 입력값이다 |
| **"최초 사건 경보"는 🟠만이 아니라 🔴·🟠(사건 계열)로 정의한다** | 오스템임플란트·위니아는 🔴가 먼저 나온다. 🟠만으로 정의하면 이 사례들의 선행 기간이 비어 버린다 |
| **검증이 끝나기 전 테스트는 삭제하지 않고 strict xfail로 남긴다** | 실패를 지우면 정답이 바뀐 이유가 사라진다. R3 연결 시험(커밋 `fe7c696`의 strict xfail 3건)과 같은 방식이다 |
| **141일은 지금 쓸 수 있지만 359일은 검증 전 쓰지 않는다** | 아래 확인 근거 참고 |

### 확인한 근거 (재현 결과)

- 가점을 켠 현재 규칙: 최초 경보 **2024-03-27 🟡 (359일)**, 최초 🟠 2024-10-31 (141일), 최종 🟠·🟡. 가점을 끄면 최초 경보가 2024-10-31 🟠(141일)이 되어 통과한다. R4 회신과 같다.
- 2024-03-27의 🟡 점수는 단기채무 3 + 이자부담 2 = **정확히 5.0**이다. 기준(5점 이상)의 경계에 걸려 있다.
- **재무 값의 출처가 불분명하다.** `collector.md` 3-3은 "재무제표 API는 정정 체인에서 최신 정정본 1건만 준다. 최초 공시 시점의 값은 얻을 수 없다"고 적는다. 금양은 2024-04-17에 `[기재정정]사업보고서(2023.12)`(`20240417000287`)가 있고, 3/27 원본(`20240327001225`)과 4/17 정정본의 저장 값(단기채무 300,628,635,695 / 현금 56,301,939,608 / 영업이익 −14,608,343,494 / 금융비용 13,512,463,313)이 **한 글자도 다르지 않다.** 둘이 같은 API 호출 결과라는 뜻이라 **3/27 원본에 실제로 이 값이 있었는지는 증명되지 않았다.**
- 🟡가 3/27~10/28 내내 유지되는 이유는 사업보고서의 이자부담 +2가 다음 분기보고서의 단기채무 +3과 **이월되어 합산**되기 때문이다(5/16 점수 구성에서 확인). 이월 자체는 설계서 "최신 정기보고서 기준" 규칙과 일치한다.
- 141일 쪽은 10/31 🟠 점수가 6.0으로 기준(4)보다 2점 여유가 있어 상대적으로 견고하다. 다만 같은 방식으로 입력을 확인한다(R3 지시 5).
- 평가 기간은 기준일 전 12개월(2024-03-21~)이라, 359일은 **이 기간 안에서 잰 값**이다. 기간 밖의 더 이른 경보는 측정하지 않았다.

R2의 수정은 필요하지 않다. 이 평가는 규칙 엔진만 쓰고(AI 추출 없음), 실패한 값은 R3 수집기 산출물과 R4 규칙, R5 정답에서 온다. R2 작업은 별도 근거가 생기기 전에는 요구하지 않는다.

## 4. R4 지시 (코드 수정이 아니라 **검증·회신**) — **R3 검증 회신 후에 전달한다**

> 지금은 R3·R5에게만 먼저 지시한다. R4는 R3 검증 결과(6절)가 나온 뒤에 이 절을 전달한다. 그때까지 R4 회신의 "R1·R5 정답 확인 필요" 항목은 열어 둔다.

현재 정책을 유지하므로 **가점을 다시 끄는 수정은 필요 없다.** 이미 있는 검증(`tests/business/test_financial_selection.py`의 0.9999/1/1.0001/0/−1, 금융비용 결합 🟡)은 중복해서 요구하지 않는다.

| # | 내용 | 종류 |
| --- | --- | --- |
| 1 | **INTEREST_BURDEN 활성화 유지** (`enabled:true`, 1 미만 +2) | 확인(변경 없음) |
| 2 | **음수 영업이익**: 금융비용이 양수이면 음수 비율 그대로 계산해 +2, 금융비용 ≤ 0이면 산정 불가. 현행 동작과 같은지 회신 | 회신 |
