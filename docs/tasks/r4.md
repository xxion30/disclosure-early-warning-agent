# R4 업무 카드 — 백엔드·도구 (양경환)

**맡는 곳**: `shared/`, `migrations/`, `risk_engine/`, `mcp_servers/business/`, `api/`, `agent/adapters/`, `harness/`의 masking·tracing·recovery_tools, `docker/`, `pyproject.toml`·`.env.example`, `scripts/ops/`, `eval/run_eval.py`, `tests/{business,risk_engine,api,wiring}/`

## 먼저 읽을 것
설계서 STEP 02(판정 규칙)·STEP 04, [contracts/risk_rules.md](../contracts/risk_rules.md), [contracts/db.md](../contracts/db.md), [contracts/api.md](../contracts/api.md), [contracts/mcp_business.md](../contracts/mcp_business.md) (모두 맨 위 "오후 회의 반영")

## 이미 되어 있는 것
구조 정리 완료(`risk_engine/`, `shared/models/` 패키지, `agent/adapters/`). 연락 업무 도구·API 복원, 영향도 제거. API는 점수 필드가 없고 등급 → 점수 → 최근 순으로 정렬하며 `GET /alerts?alert=true`가 대시보드 알림을 준다. 규칙은 아직 이전 Low~Critical.

## 할 일 (순서대로)
1. **0단계 계약**: `rules.yaml` 새 구조 초안(🔴 항목 목록, 🟠·🟡 점수표, 기준값, 복합 비율, 관찰 기준, 단계 정렬 순서)을 먼저 문서(`contracts/risk_rules.md`)로 내서 R1·R2에게 확인받는다. 재무 지표 표는 R3와 합의한다.
2. **규칙 엔진 재작성**(`risk_engine/`): `rules.yaml` → `risk_rules.py`를 단계 판정(🔴 즉시, 🟠·🟡 점수, 복합, 관찰)으로. 시간 반영(6개월 100%, 6~12개월 50%)·정정 공시 처리는 재사용. 숫자는 yaml에서만 읽는다. 파일을 red/orange/yellow/stage로 나눌지는 이때 정한다(정리 PR에서 미룬 것).
   - 완료: 기존 5개 회사 사례와 단위 테스트가 통과하고, "점수 높은 순" 정렬 키(등급 → 점수 → 최근)를 규칙이 돌려준다.
3. **DB 모델 변경**: `level` → `stage`, `risk_states`·`financial_snapshots`·`collect_runs`·`tenants` 추가, `tenant_id`. 기존 DB는 칸 추가 방식 유지.
4. **business-mcp 도구**: 위험 상태 조회·저장, 수집 이력, 노출 조회. `calculate_risk_score`가 새 규칙을 쓰도록.
5. **API**: `/states`, `/states/{stock_code}`, `/collect/status`, `/collect/run`, `/customers`. **점수 필드는 내보내지 않는다.** 응답은 서버가 우선순위로 정렬해서 준다. 오류 형식 `{ok:false,error}` 유지.
6. **PostgreSQL + Alembic**: `migrations/`, `docker/`, docker compose. 회사(`tenant_id`) 자동 필터(로그인은 기존 JWT, SSO 없음).
7. 큐는 Phase 1에서 끄고 코드만 보존. 새 시나리오에 맞게 `scripts/ops/verify_all.py`를 다시 쓴다(지금은 옛 기준).
8. 의존성·환경 변수 추가 요청을 받아 `pyproject.toml`·`.env.example`에 반영한다.

## 하면 안 되는 것
계약(DB·API·MCP) 변경을 문서 없이 먼저 코드로 바꾸지 않는다. `agent/`의 그래프·프롬프트는 R2 영역이다.
