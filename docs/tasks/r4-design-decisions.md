# R4 설계 결정 추천안

- 작성일: 2026-10-22
- 상태: **R4 구현 기준으로 채택**. 이 대화에서 정한 적용·보류·제외 범위를 아래에 기록한다. 연결 담당자의 계약 확인은 별도다.
- 기준: 기획서와 역할·계약 문서의 명세를 따르며, 오후 회의 변경을 우선한다. 기존 코드 구조는 설계 제약으로 삼지 않는다.

## 전제

점수·단계는 규칙이 계산하고, 점수 숫자는 YAML에서 관리한다. PB 응답에는 점수를 노출하지 않는다. 연락 대상은 보유 고객 전원이며, PB 승인 후 연락 업무를 생성한다. 직접 발송과 고객 영향도(P1~P3)는 제외한다.

경보 기준은 현재 초안인 🟠 4점, 🟡 5점, 복합 비율 1.5로 먼저 검증한다. 아래 내용은 그 기준을 구현하기 위해 추가로 합의할 사항이다.

## 1. 점수 구간과 합산

**추천:** 같은 지표의 구간은 해당 구간의 최댓값만 적용하고, 서로 다른 조건은 합산한다. 소송 비율 10% 이상은 +3만 적용한다. 유상증자는 20% 이상 +1, 50% 이상 추가 +1로 명시한다.

**근거:** 동일 사실의 중복 가점을 막고, 유상증자의 단계별 추가 위험은 구분할 수 있다. YAML에서도 구간 선택과 독립 조건 합산을 구별해야 한다.

## 2. 정성 조건과 미확정 수치

**추천:** AI의 조건 판정은 `true / false / unknown`으로 구분하고, `true`에는 근거 인용을 요구한다. 핵심자산·긴급 자금 확보·부실 이전의 인정 조건을 정의한다. “출자 규모가 큼 +1~2”는 수치 기준 확정 전까지 자동 가점을 보류하고 수동 확인 대상으로 표시한다.

**근거:** AI가 임의로 점수를 정하거나, 근거 부족을 위험 없음으로 처리하는 것을 방지한다.

## 3. 미분류 위험 항목

**추천:** 회사 자신의 실제 원리금 미지급은 RED에 포함한다. 단순 미상환 잔액·만기 도래와는 구분한다. 채무보증은 근거만 기록하고 독립 점수화는 Phase 2로 미룬다. 주요 계약 해지도 Phase 2로 미룬다.

**근거:** 실제 지급 불이행은 즉시 경보 목적에 부합한다. 보증과 계약 해지는 규모·맥락에 대한 별도 규칙이 필요하며, 계약 해지 제외는 기존 호재 정정·해지의 Phase 2 분류와도 맞는다. 원리금 미지급의 RED 편입은 R1의 범위 승인이 필요하다.

## 4. 관찰 기준

**추천:** 경보 기준의 75% 이상으로 통일한다. 현재 기준에서는 🟠 3점, 🟡 3.75점이며 반올림하지 않는다. 경보·복합 판정에 해당하지 않을 때만 WATCH를 적용한다.

**근거:** 문서의 “🟡 4점”과 “75%”는 소수점 점수에서 결과가 달라진다. 비율로 정의하면 경보 기준 변경 시에도 일관성을 유지한다.

## 5. 시간 경과와 해소

**추천:** 🟠의 시간 감쇠·만료에 따라 현재 단계를 재계산하되, 이를 “해소됨”으로 표시하지 않는다. 해소는 확인된 공시가 있을 때만 기록한다. RED는 시간만으로 제거하지 않고, 🟡는 최신 정기보고서로 갱신한다. 신규 공시가 없는 날에도 일일 재계산한다.

**근거:** 점수의 유효기간과 위험의 실제 해소는 다르다. 두 상태를 분리해야 시간 가중치와 보수적 해소 원칙을 함께 지킬 수 있다.

## 6. 동시 경보와 정렬

**추천:** 🟠·🟡 동시 경보는 모두 보존하고 대표 단계는 ORANGE로 표시한다. 같은 우선순위의 ORANGE와 COMPOSITE는 기준 대비 비율로 비교한다. ORANGE는 `orange_score / orange_threshold`, COMPOSITE는 합산 비율을 사용한다. 동점은 최근 근거 공시, 종목코드 순으로 정렬한다.

**근거:** 원점수와 합산 비율을 직접 비교하면 단위가 달라 정렬이 왜곡된다. 대표 단계와 개별 판정을 분리하면 🟡 근거도 보존할 수 있다. 이 정렬 방식은 기존 계약을 보완하는 합의가 필요하다.

## 7. 연락 업무 재생성

**추천:** 단계 상승·새 위험 종류·새 RED 발생으로 새 알림 사건이 생길 때 연락 검토를 시작한다. 같은 종류의 근거 추가는 타임라인만 갱신한다. 미승인 초안은 최신 사건에 맞춰 갱신하고 변경 사실을 표시한다. 승인된 안내문·업무는 자동 수정하지 않는다. 승인 대기 중 위험이 해소되면 기존 초안 승인을 막고 재확인을 요구한다.

**근거:** 반복 공시로 업무가 중복 생성되는 것을 줄이고, 승인 당시 내용과 기록을 보존한다.

## 8. 읽음 상태

**추천:** 읽음은 PB별·알림 버전별로 저장한다. 새 알림 사건이 발생하면 `new: true`로 전환하고, 단순 근거 갱신은 읽음을 유지한다. 새로 보유한 종목의 기존 경보는 해당 PB에게 처음 한 번 새 알림으로 표시한다.

**근거:** PB마다 확인 여부가 다르며, 이미 읽은 경보와 새 위험을 구분해야 한다. 읽음은 승인·해소와 별개다.

## 9. 수동 수집과 실패 처리

**추천:** 역할은 PB와 회사 관리자로 구분한다. 수동 수집은 관리자가 자기 회사 보유 종목에 대해서만 요청한다. 정기 수집은 전체 회사 보유 종목의 합집합을 대상으로 한다. 동일 종목이 수집 중이면 기존 실행을 반환하고, 증분 기준은 종목별 성공 범위까지만 전진시킨다.

**근거:** 실행 중복을 막고, 일부 종목의 실패로 공시가 누락되는 것을 방지한다. 큐 없이도 실행 잠금과 DB 이력으로 관리할 수 있다.

## 10. R3 ↔ R4 재무 데이터 계약

**추천:** 지표명·단위·기간·연결/별도 구분·원천 필드·접수번호·수집 시각·계산식·결측 상태를 명시한다. 연결재무제표를 우선하고, 없으면 별도를 사용하되 기준을 기록한다. 정정본은 이전 이력을 보존한 새 버전으로 반영한다. 결측은 0과 구분하고, 확인된 경보와 수동 확인 필요 상태를 함께 표시할 수 있게 한다.

**근거:** 기간·회계 기준 혼용과 결측의 0점 처리를 막고, 판정 결과를 재현할 수 있다. 확인된 위험이 다른 항목의 결측 때문에 숨겨져서도 안 된다.

## 11. R2 ↔ R4 실행 상태 계약

**추천:** 공개 공시 분석·종목 위험 판정은 공유하고, 고객 초안·승인·연락 업무는 회사별로 분리한다. 고객 업무 체크포인트 식별자에는 회사와 알림 사건을 포함한다. PB 권한은 요청마다 서버에서 확인한다.

**근거:** 동일 공시의 중복 분석을 줄이면서 고객 정보와 승인 상태의 회사 간 혼합을 막는다. 기존 `thread_id = rcept_no` 계약은 고객 업무 분리에 맞게 개정해야 한다.

## 12. R4 ↔ R5 API 계약

**추천:** 알림은 `GET /states?alert=true`를 기본으로 한다. 목록에는 대표 단계·활성 위험 종류·새 알림 여부·최근 변경·해소·수동 확인 상태를 제공한다. 상세에는 설명·인용·출처·타임라인을 제공한다. 점수·내부 정렬값은 제외한다. 서버 정렬 후 페이지를 나누고, 수집과 분석 진행은 구분한다.

**근거:** 프론트가 점수나 그래프 구현에 의존하지 않고 개발할 수 있으며, 페이지를 넘어도 정렬이 일관된다.

## 13. 원문 수명과 복구

**추천:** 원문·검색 색인은 분석과 초안 생성 중 메모리에서만 유지한다. 승인 대기 전 State·체크포인트에서도 원문을 제거한다. 설명·초안·검증된 인용·출처·해시는 저장한다. 승인에는 저장된 근거를 사용하고, 재작성·복구에 원문이 필요하면 DART에서 재조회한다. 해시가 달라지면 재분석한다.

**근거:** 원문 영속 저장 금지를 지키면서 승인·재작성·재시작을 지원한다. 체크포인트를 통한 원문 우회 저장도 방지한다.

## 합의와 반영

- **1~8:** R1 중심으로 판정·알림·연락 정책을 합의하고 R2·R4·R5가 관련 계약에 반영한다.
- **9~13:** R4가 계약 초안을 작성하고 R2·R3·R5와 연결 경계를 확정한다. 수동 수집 권한은 R1도 확인한다.
- 재무 지표와 수집 형식은 R3 초안·R4 확인을 따른다. 점수 값은 R1이 확정하고 R4가 YAML에 반영한다.
- 합의 결과는 각 계약 문서에 먼저 반영한다. 이 문서는 추천 근거를 남기는 기록으로 유지한다.

## 추가 결정 (2026-10-22)

- 원공시·정정·후속 공시는 `event_id`로 연결한다. 별도 사건만 반복 횟수에 포함하며, 단순 정정으로 최초 발생일을 초기화하지 않는다. 연결 정보가 불확실한 정정은 점수에 중복 합산하지 않고 수동 확인으로 남긴다.
- 위험 항목 간 중복 합산 정책은 실제 데이터 확인 후 결정한다. 통합 규칙을 임의로 적용하지 않고, 구현 후 로그에 한계를 기록한다.
- 연속 연도는 연간 자료끼리, 분기 추세는 같은 기간·누적 기준끼리 비교한다. 분모 0·음수·결측은 정상 계산과 구분하며 판단 불가 시 수동 확인한다.
- 승인 대기 중 보유·담당 PB 변경 대응은 범위에서 제외한다. 기존 담당 PB 권한 검사는 유지한다. 8절의 신규 보유 고객 자동 알림도 이번 구현에서 제외한다.
- 해소 후 동일 위험 재발 전용 감지·재알림은 범위에서 제외한다. 기존 단계 상승·새 종류·새 RED 알림 원칙은 유지한다.
