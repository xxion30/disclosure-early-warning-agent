# R5 업무 카드 — 프론트·데모·검증 (박세호)

**맡는 곳**: `web/`, `scripts/demo/`, `tests/demo/`, `docs/verification.md` (QA·평가 겸임)

## 먼저 읽을 것
설계서 STEP 04(화면)·STEP 06(평가), [contracts/api.md](../contracts/api.md) 맨 위 "오후 회의 반영"

## 이미 되어 있는 것
경보 목록(상단 **경보 알림** 카드: 등급 → 점수 순, 점수 숫자 없음), 경보 상세(위험 항목 표·근거 인용), 안내문 검토, 연락 업무, 고객 현황 화면이 이전 규칙 기준으로 돈다. 점수·P1~P3 배지는 제거됐다.

## 할 일 (순서대로)
1. **0단계 계약**: R4가 내는 API 응답(점수 비노출, 정렬, `?alert=true`, 새 `stage` 값)을 확인하고, 화면에 필요한 필드를 요청한다 (API 변경은 R4 파일이니 요청으로).
2. **새 단계 배지**: 🔴/🟠/🟡/복합/관찰 배지(`LevelBadge`, `labels.js`)와 단계·상태 필터. 점수 숫자는 어디에도 표시하지 않는다.
3. **종목 상세**: 상단 요약 카드(이번에 무엇이 바뀌었나), 위험 항목·근거(API 값 또는 원문 인용 + DART 링크), 공시 타임라인, 해소 표시, "확인함"(읽음 표시일 뿐).
4. **메인 대시보드 알림**: 경보 알림을 우선순위순으로, "새 경보" 표시(단계가 올라갔거나 새 종류 근거가 추가됐을 때만), 마지막 수집 시각·수집 실패 표시.
5. **고객 현황·안내문 검토·연락 업무**: 새 단계 값에 맞게 수정 (PB는 자기 담당 고객만 승인 — 403 처리).
   - 완료: 가짜 데이터(`--fake` 모드)로 위 화면이 모두 보인다.
6. **통합 시연**: 종목 1개로 수집 → 판정 → 안내문 → PB 승인 → 연락 업무까지 한 번에. 시나리오와 영상 촬영. 옛 `scripts/demo/check_scenario_a.py`·`smoke.py`를 새 시나리오로 다시 쓴다.
7. **검증·평가**(QA): 테스트 사례 세트(`eval/cases/r5_*`, R3와 나눠 씀)로 경보 적중·경보 빈도·오탐 표를 만들고, 기준값 변경 전후 비교를 `docs/verification.md`에 쓴다. README.

## 하면 안 되는 것
API·서버 코드는 고치지 않는다(R4에게 요청). 점수 숫자를 화면에 다시 넣지 않는다.
