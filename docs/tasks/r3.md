# R3 업무 카드 — RAG·데이터 (한예빈)

**맡는 곳**: `collector/`, `mcp_servers/rag/`, `rag_docs/`, `data/`, `scripts/data/`, `shared/models/collect.py`, `tests/{collector,rag}/`

## 먼저 읽을 것
설계서 STEP 03(데이터), [contracts/data_sources.md](../contracts/data_sources.md), [contracts/mcp_rag.md](../contracts/mcp_rag.md)

## 이미 되어 있는 것
이전 프로젝트의 DART 다운로드 스크립트(`scripts/data/fetch_dart.py`)와 RAG 색인(`mcp_servers/rag/`, Chroma)이 있다. 새 설계용 수집기(`collector/`)는 뼈대만 있다.

## 할 일 (순서대로)
1. **가장 먼저: OpenDART API 확인** — 위험 항목(🔴🟠🟡)마다 어떤 API가 값을 주는지, 회사 단위 조회, 호출 한도, 공시 지연, 정정 공시 방식을 실제로 호출해 확인한다.
   - 완료: **데이터 출처표**(항목 → API/제목 감지 → 구조화 값 여부 → 한계)와 API 확인 메모가 `docs/contracts/data_sources.md`에 올라가고 R1·R4가 읽었다. 거래소 공시(거래정지·관리종목·상장폐지·횡령·배임)는 정리된 값 API가 없을 수 있어 제목 감지 + 원문 읽기로 처리한다.
2. **0단계 계약**: 재무 지표 표(`financial_snapshots`) 컬럼과 수집 결과 형식을 정해 R4와 합의한다 (수집기와 규칙 엔진은 **DB 표로만** 만난다).
3. **수집기**: 보유 종목 합집합 읽기(ETF 제외) → 종목별 증분 조회 → 백필 → 재시도·호출 속도 제한 → 수집 이력(`collect_runs`). `httpx`(async) + `tenacity`, 매일 09:05 APScheduler.
   - 완료: 종목 1개로 "지난 수집 이후" 공시만 받아 DB에 들어가고, 수집 이력이 남는다. 한도 초과 때 재시도한다.
4. **재무 지표 모듈(🟡)**: 자본잠식, 영업현금흐름, 이자보상배율, 단기채무 비율 계산 → `financial_snapshots`.
5. **rag-mcp를 메모리 임시 색인으로**: Chroma 영속 저장을 없애고 처리 중에만 색인한다 (원문은 저장하지 않는다). `release_disclosure_index`·`purge_disclosure_text`는 이때 정리한다(복원 때 함께 돌아옴).
6. **참고 문서 재작성**(`rag_docs/reference/`): 새 위험 항목 해설. 안내문 가이드(`message_guide.md`)는 유지.
7. **테스트 사례 수집**(`eval/cases/r3_*`): 실제 과거 사례만(🔴🟠🟡 단계별 + 정상). R5와 `eval/cases/`를 나눠 쓴다(파일 이름에 `r3_`).
8. 새 수집기가 돌면 `rag_docs/companies/`, `data/disclosures/`, `data/demo_companies.json`, 옛 스크립트를 삭제한다 (RAG 색인·seed·테스트가 참조하니 마지막에, 별도 PR).

## 하면 안 되는 것
공시 내용·접수번호를 지어내지 않는다. 점수 계산(`risk_engine/`)은 R4다. 원문을 DB·디스크에 남기지 않는다.
