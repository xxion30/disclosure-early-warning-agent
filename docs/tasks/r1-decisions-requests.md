# R1 결정과 담당별 요청 (2026-10-23)

R1이 [위험 정책](../risk_policy.md)에 확정한 내용 중 **다른 담당의 파일을 바꿔야 하는 것**만 모았다. 각 담당은 자기 파일을 고치고, 못 하는 것은 "알려진 한계"로 문서에 적은 뒤 R1에게 알린다. 결정의 근거와 원칙은 [위험 정책](../risk_policy.md) 1~3장에 있다.

우선순위: **높음**은 오늘(기능 중단 전) 안에, **중간·낮음**은 시간이 될 때. 못 하면 한계로 기록한다.

## R4 (`risk_engine/`, `api/`, `mcp_servers/business/`, `docs/contracts/risk_rules.md`)

| # | 요청 | 우선순위 |
| --- | --- | --- |
| 1 | **자본잠식을 개별(OFS)·연결(CFS) 둘 다 계산**하고 하나라도 기준을 넘으면 켠다. 점수는 높은 구간 하나만, 근거에 `fs_div` 표시. 지금은 최신 OFS만 쓰고 CFS 대체를 막아 둔 상태 | 높음 |
| 2 | **이자보상배율 `enabled:false`를 해제**하고 경계값 `1 미만 +2`를 `rules.yaml`에 반영. 계정을 못 찾으면 0점이 아니라 "산정 불가" 유지 | 높음 |
| 3 | **원리금 미지급 🔴 편입의 구현 비용을 알려 준다.** 가능하면 반영, 어려우면 근거를 남기고 알림은 주는 방식 | 높음 |
| 4 | `매매거래정지및정지해제(풍문등조회공시)`를 **관찰 중** 규칙에 넣는다 | 중간 |
| 5 | **관리종목 변형 제목을 🔴로** 인식 (제목 후보는 R3 → `rules.yaml` 반영은 R4) | 중간 |
| 6 | **횡령·배임 사실확인 "첫 관측이면 🔴" 규칙.** `event_id`로 앞선 🔴 사건이 없을 때만 새로 켠다 | 중간 |
| 7 | 자회사·종속회사 **두 표기 모두 인식**, 점수는 넣지 않고 응답에 "참고" 표시 필드를 제공 | 낮음 |
| 8 | 근거 응답에서 **어떤 지표가 켜졌는지** PB 화면에서 구분되게 필드를 제공 (금융업 연결 사례 등) | 낮음 |
| 9 | `docs/contracts/risk_rules.md` 5-1 표가 아직 "감사의견 거절·부적정 → Critical"(이전 규칙)이다. 설계서 기준(🟡 재무 경보, +5)으로 정정 | 중간 |
| 10 | `docs/run.md`의 시나리오 설명(감사의견 거절 → Critical, P1 5·P2 2)을 새 기준으로 정정 | 낮음 |

## R3 (`collector/`, `mcp_servers/rag/`, `data/`, `docs/contracts/data_sources.md`)

## R5 (`web/`, `eval/cases/r5_*`, `docs/verification.md`)

| # | 요청 | 우선순위 |
| --- | --- | --- |
| 1 | `eval/cases/r5_*`의 **금양·CJ CGV 정답**을 [위험 정책 3-3](../risk_policy.md)대로 변경 (금양: 🟠 먼저 + 🟡 추가, CJ CGV: 🟠) | 높음 |

| 4 | 발표·영상 메시지는 **"사건 141일 전 조기경보"** 로 통일 | 높음 |
