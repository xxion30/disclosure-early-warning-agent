# R2 업무 카드 — AI 흐름 (윤찬웅)

**맡는 곳**: `agent/`(`adapters/` 제외), `harness/`의 context·guardrails·loop_limits·recovery_llm, AI 평가 실험(`eval/experiments/`), `tests/agent/`

## 먼저 읽을 것
설계서 STEP 05(AI 처리 흐름), [contracts/agent.md](../contracts/agent.md) (맨 위 "오후 회의 반영"), [contracts/harness.md](../contracts/harness.md)

## 이미 되어 있는 것
분석 → 설명 → 안내문 초안 → 검사 → PB 승인(interrupt) → 연락 업무 그래프가 돈다. 연락 대상은 보유 고객 전원(`find_customers`는 `get_holders` 사용). 프롬프트는 `agent/prompts/*.md`, `explain_risk.md`는 v3(점수 숫자 언급 금지).

## 할 일 (순서대로)
1. **0단계 계약**: R4가 내는 `rules.yaml` 구조 초안과 State 변경을 확인한다. State 변경은 `contracts/agent.md`를 먼저 고친다.
2. **새 그래프 골격**(가짜 도구로 먼저): `classify`를 🔴/🟠/🟡 항목 매핑으로, `extract_facts` → `extract_flags`(텍스트 필드만 AI), 🟡은 코드 계산(`compute_indicators`), `judge_stage`(규칙) 노드를 설계서 STEP 05 그래프대로 만든다. 경보 단계(🔴·🟠·🟡·복합)일 때만 안내문 구간으로 간다. 관찰·없음은 저장에서 끝난다.
   - 완료: 가짜 도구로 🔴 1건, 🟠 점수 경계 사례, 정상 사례 3개가 그래프를 끝까지 돈다 (`tests/agent/`).
3. **프롬프트**: `extract_flags.md` 새로 작성, `explain_risk.md`(점수 숫자 금지 유지)·`system.md` 수정. 바꿀 때마다 `version:` 을 올린다.
4. **Harness**: 금지 표현 검사를 설명문과 안내문 양쪽에 건다(`guardrails.py`), DART 오류 재시도 규칙(`recovery_llm`과 R4의 `recovery_tools` 경계는 합의).
5. **R4의 진짜 규칙·도구로 교체** → 통합 시나리오에서 근거 인용(원문에 글자 그대로 있는지)이 검증되는지 확인.
6. **체크포인트 PostgreSQL 전환**(`langgraph-checkpoint-postgres`, `agent/runtime.py`)은 R4의 DB 전환 시점에 맞춘다.
7. **AI 평가 실험**(`eval/experiments/`): 모델 기본/대체, RAG k, 가드레일 켬/끔 전후 표.

## 하면 안 되는 것
AI 출력에 점수·단계 필드를 넣지 않는다. 고객 실명을 모델에 보내지 않는다. `agent/adapters/`·`api/`·`risk_engine/`은 R4 영역이다.
